# 第 6 课：可空类型与空值处理

今天学习如何表达“可能没有值”，以及遇到空值时该怎样继续执行。先掌握 `String?`、`?.` 和 `?:`，再练习输入转换。

练习文件：`basics/src/main/kotlin/com/example/kotlinlearn/basics/lesson06/Lesson06.kt`。

## 1. null 表示没有值

```kotlin
val name: String = "小明"
val nickname: String? = null
```

`String` 表示非空字符串类型；`String?` 在它的基础上允许 `null`。类型后面的 `?` 是声明的一部分。

| 写法 | 含义 |
| --- | --- |
| `null` | 没有值，没有字符串可供读取 |
| `""` | 存在一个字符串，长度为 0 |
| `"null"` | 存在一个字符串，内容是四个字母 |

所以不能写 `val name: String = null`。如果数据可能缺失，需要声明为可空类型。

`val` / `var` 决定是否能重新赋值；`String` / `String?` 决定是否允许 null，两者是不同的问题。`val nickname: String? = null` 是合法的，但不能在同一次执行中再给这个 `val` 赋一个新值。

## 2. ?.：有值才访问

先看 `describeNickname` 中这一行：

```kotlin
val originalLength: Int? = nickname?.length
```

`length` 是字符串的长度属性。`nickname?.length` 表示：nickname 非空时读取长度，nickname 为 null 时整个表达式得到 null。

因此结果类型是 `Int?`，不是 `Int`。安全调用并不会自动给你一个数字 0。

如果在这个接收可空参数的函数里直接写 `nickname.length`，编译器会要求你先处理可能的 null。

## 3. ?:：空值时选择默认值

```kotlin
val displayName: String = nickname ?: "游客"
val shownLength: Int = originalLength ?: 0
```

`?:` 称为 Elvis 运算符。左边不为 null，就使用左边的值；左边为 null，才使用右边的值。右边也只在需要时求值。

因此默认例子会显示“游客”，并把缺失的原昵称长度显示为 0。这是我们选择的显示方式，并没有把 `nickname` 本身改成“游客”。

安全调用与默认值也可以连起来写：

```kotlin
val shownLength: Int = nickname?.length ?: 0
```

比较这几种输入：

| nickname | nickname?.length | nickname ?: "游客" |
| --- | --- | --- |
| `null` | `null` | `"游客"` |
| `"小明"` | `2` | `"小明"` |
| `""` | `0` | `""` |
| `"null"` | `4` | `"null"` |

特别注意：`?:` 只判断 null。空字符串、数字 0、布尔值 false 都不会触发这个默认值。如果产品规则认为空字符串或空白文字也算未填写，需要另外判断。

## 5. 数量输入不一定能转成整数

输入框提供的是文字。字符串 `"3"` 可以转成整数，`"abc"` 则不能。

```kotlin
val quantity: Int? = input.toIntOrNull()
```

`toIntOrNull()` 成功时返回 `Int`，输入格式不对或超出 `Int` 范围时返回 null，因此整个调用的类型是 `Int?`。

本课没有给无效输入随便安排一个购买数量，而是返回明确的提示：

```kotlin
if (quantity == null) {
    return "请输入有效的整数。"
}

if (quantity <= 0) {
    return "数量必须大于 0。"
}
```

这两步处理不同的问题：

1. 能不能转换为整数？例如 `"abc"` 转换失败。
2. 整数是否符合购买规则？`"0"` 和 `"-2"` 转换成功，但数量不是正数。

## 6. 为什么判断以后可以直接使用 quantity？

这里的 `quantity` 是局部 `val`，值不会重新赋予。为 null 的情况已经 `return`，所以后面的代码只可能接收到非空值。

编译器会利用这个判断，在后面把 `quantity` 当作 `Int` 使用。这叫智能转换，不需要写 `quantity!!`。

`!!` 是非空断言：如果实际值为 null，会抛出空指针异常。它不提供默认值，也没有把缺失数据补齐。本课练习用安全调用、默认值和明确的 null 判断来处理数据。

## 7. 默认完整输出

```text
昵称示例
当前昵称：显示名称：[游客]，原昵称长度：0
有值对照：显示名称：[小明]，原昵称长度：2
空字符串：显示名称：[]，原昵称长度：0
文字 null：显示名称：[null]，原昵称长度：4

数量输入示例
当前输入（3）：购买 3 本，总价 37.5 元。
输入 abc：请输入有效的整数。
输入 0：数量必须大于 0。
输入 -2：数量必须大于 0。
超出 Int 范围：请输入有效的整数。
```

显示名称外面的方括号只用于让空字符串看得更清楚，并不是昵称本身的一部分。长度统计的是原始昵称；默认显示“游客”时，不会改为统计“游客”的长度。

## 8. 动手练习

每次只改一个值，先预测，再运行：

1. 把 `nickname` 改成 `"Kotlin"`：显示名称和原昵称长度分别是什么？
2. 改成 `""`：为什么没有显示“游客”？
3. 把 `quantityInput` 改成 `"4"`、`"abc"`、`"0"`，观察三种不同的结果。
4. 加练：尝试 `""`、`"-2"`、`"2147483648"`，判断是转换失败还是不符合数量规则。

前后的空格也会影响本例的转换，例如 `" 3 "` 不会直接转为 Int。如果需要接受这样的输入，可先使用 `input.trim().toIntOrNull()` 去掉两端空白，再转换；这是额外的输入处理规则。

学完后，你应该能解释三个问号写法的区别：类型上的 `?` 允许空值，`?.` 安全访问，`?:` 为 null 提供替代结果。下一课学习集合，用 List、Set、Map 管理多条数据。
